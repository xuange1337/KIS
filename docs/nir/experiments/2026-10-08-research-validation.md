## Идентификация версии

Дата: 08.10.2026. Базовый commit: `122a1cfb2d529da68540df4324ebe183d41b389f`, версия пакетов 1.1.0. Использовано изменённое рабочее дерево, включая каталог и состав КП. Commit сам по себе не воспроизводит эту версию; контрольные суммы файлов приведены в [source-manifest.json](artifacts/2026-10-08/source-manifest.json).

## Стенд

Хост: Apple M2, 8 логических CPU, 16 GiB RAM, macOS/Darwin 27.0.0. Docker Desktop: 8 CPU и 8 321 994 752 байта памяти. PostgreSQL 17.11, NestJS 11.2.5, Node.js 22.23.3 в API; инструменты на хосте и генератор нагрузки — Node.js 26.3.0. API и nginx работают в отдельных контейнерах, клиент нагрузки — на хосте.

Экспериментальный проект `kis-nir` использует отдельные сеть, тома и порт PostgreSQL 55432; web доступен только на `127.0.0.1:8181`. База `crm_nir` используется для нагрузки, `crm_test` — для API и браузерных сценариев, `crm_nir_restore` — для проверки восстановления. Рабочая база обычной CRM не изменялась этими командами.

Docker Registry вернул TLS handshake timeout при сборке. Поэтому использованы локальные runtime-образы `kis-api` и `kis-web` с bind mount **текущих собранных** `server/dist`, `packages/shared/dist`, `web/dist` и конфигурации nginx. Версии прямых production-зависимостей API совпали с lock-файлом ([сохранённые версии](artifacts/2026-10-08/api-dependencies.json)); этот способ запуска не является подтверждением сборки новых самостоятельных Docker-образов. [Идентификаторы образов](artifacts/2026-10-08/images.txt), [ресурсы Docker](artifacts/2026-10-08/docker-resources.txt), [версия PostgreSQL](artifacts/2026-10-08/postgres-version.txt).

На хосте оставались другие приложения и контейнеры. Ресурсная изоляция от них не обеспечивалась; результаты характеризуют данный локальный прогон, а не выделенный промышленный сервер.

## Проверка ограничения запросов

Штатный лимит общего API — 120 запросов за 60 секунд. При 130 последовательных обращениях к `/api/dashboard` получено 120 ответов 200 и 10 ответов 429; первый отказ — на запросе 121. [Машинный результат](artifacts/2026-10-08/throttle.json).

Предварительный нагрузочный запуск с включённым лимитом также получил 429. Быстрые ответы с отказом не включаются в вывод о производительности успешных операций. Для измерения скорости `RATE_LIMIT_DISABLED=true` установлено **только в экспериментальном API**. В тестах входа использован отдельный экспериментальный лимит 200. Измерения не обосновывают отключение защиты при эксплуатации.

## Нагрузочное измерение

Модель — closed-loop без времени на действия человека: каждый worker отправляет следующий запрос после полного получения и декодирования ответа. Используются 30 сессий всех трёх ролей и организаций; вход исключён из измерения. Перед каждой ступенью выполняются 30 последовательных прогревочных запросов.

Маршруты: списки клиентов, сделок и активностей с `limit=25`, дашборд, воронка RUB и поиск клиентов `q=100`. Ступени параллелизма — 1, 10 и 30; на каждой три повтора по 50 запросов на worker. p50 и p95 рассчитаны методом nearest rank. Критерий локального smoke-прогона: отсутствие ошибок и p95 не выше 800 мс. Сырые длительности, HTTP-статусы, сводки по маршрутам и условия приведены в [load.json](artifacts/2026-10-08/load.json).

| Параллельных workers | Запросов за три повтора | p50 по повторам, мс | p95 по повторам, мс | Запросов/с по повторам | Ошибки |
|---|---:|---|---|---|---:|
| 1 | 150 | 4,70–5,66 | 8,17–9,91 | 170,21–205,65 | 0 |
| 10 | 1 500 | 14,10–15,38 | 19,85–23,33 | 625,55–682,00 | 0 |

Всего 6 150 измеренных запросов; прогревочные запросы учитываются отдельно. Таблица показывает диапазоны метрик отдельных повторов, а не перцентили объединённой выборки. Длительность одного повтора — примерно 0,24–2,14 секунды. Это короткое измерение чтения на прогретой базе; оно не определяет предельную пропускную способность, устойчивость к длительной нагрузке, скорость массовых изменений или тяжёлых выгрузок. Достигнутый критерий относится только к описанным условиям.

## Резервное копирование и восстановление

[nir-backup-check.mjs](../../../scripts/nir-backup-check.mjs) создал PostgreSQL custom dump и tar-архив синтетического файла. API эксперимента был остановлен на время копирования и сравнения, чтобы фоновые процессы не меняли записи. Дамп восстановлен в новую `crm_nir_restore`; существующая база не перезаписывается скриптом.

Для 18 таблиц, включая миграции и служебные таблицы, совпали количества строк и MD5 упорядоченного логического представления строк. MD5 здесь используется для сравнения содержимого, а не для криптографического доказательства подлинности. SHA-256 дампа и архива сохранены в `SHA256SUMS`; после распаковки совпало содержимое контрольного файла. Дамп — 1 618 173 байта, архив — 10 240 байт.

Копия находится в `backups/nir-2026-10-08/` и исключена из Git. [Паспорт копии и сравнение таблиц](artifacts/2026-10-08/backup.json). Проверена локальная синтетическая база и один синтетический файл; промышленное восстановление, внешнее хранилище, непрерывное архивирование WAL и гарантированное RPO/RTO не измерялись.

## Воспроизведение

Все команды выполняются из корня репозитория. Нужны установленные зависимости, Docker, текущие исходники и локальный `.env`; его значения не публикуются.

```bash
npm run build
# Основной путь: сборка текущих самостоятельных образов.
docker compose --env-file .env -f docs/nir/compose.experiment.yml up -d --build --wait
# Автономный путь данного прогона: те же текущие сборки на локальных runtime-образах.
docker compose --env-file .env -f docs/nir/compose.experiment.yml -f docs/nir/compose.cached.yml up -d --no-build --wait
POSTGRES_HOST=localhost POSTGRES_PORT=55432 npm run ci
POSTGRES_HOST=localhost POSTGRES_PORT=55432 POSTGRES_DB=crm_nir NIR_ALLOW_SEED=1 \
  NIR_DATASET_REPORT=docs/nir/experiments/artifacts/2026-10-08/dataset.json node scripts/nir-seed.mjs
node scripts/nir-throttle-check.mjs docs/nir/experiments/artifacts/2026-10-08/throttle.json
NIR_RATE_LIMIT_DISABLED=true docker compose --env-file .env -f docs/nir/compose.experiment.yml \
  -f docs/nir/compose.cached.yml up -d --no-build --wait
node scripts/nir-load.mjs docs/nir/experiments/artifacts/2026-10-08/load.json
node scripts/nir-backup-check.mjs docs/nir/experiments/artifacts/2026-10-08/backup.json
```

Основной и автономный пути запуска являются альтернативами. Для повторного полного эксперимента нужен новый чистый том БД; генератор и проверка копии останавливаются при наличии исходных данных или существующей базы восстановления. Предыдущие артефакты следует сохранять в другом каталоге прогона. При повторе контроля лимита процесс экспериментального API должен быть запущен заново, чтобы старые счётчики не влияли на результат.

Браузерные тесты запускаются с дополнительным `compose.browser.yml` после подготовки свежей `crm_test`; используется `E2E_BASE_URL=http://127.0.0.1:8181 npx playwright test`. Перед новым измерением нагрузки необходимо убрать браузерный override и вернуть базу `crm_nir`.
