# Эксперимент: каталог и состав коммерческого предложения

Дата: 08.10.2026. Базовый commit: `122a1cf`, изменения текущего рабочего
дерева. Версия пакетов: 1.1.0; изменения ещё не выпущены.

## Проверяемые положения

1. Каталог доступен сотрудникам только своей организации; изменения
   доступны руководителю и администратору.
2. Предложение сохраняет снимок названия, единицы и цены, а также валюту.
3. Итог рассчитывается сервером в целых копейках с округлением каждой строки.
4. Замена состава выполняется транзакционно; недопустимая строка не оставляет
   частично изменённый документ.
5. Проверка версии предотвращает потерю правок при параллельном сохранении.

## Среда и воспроизведение

Локальный стенд: Docker с PostgreSQL 17, NestJS API, React UI.
Используются отдельные базы `crm_test` и `crm_migration_test`; тестовые
фикстуры синтетические. API-тесты автоматически пересоздают тестовую базу,
применяют миграции и загружают seed. Рабочая база `crm` не обновлялась.

```bash
docker compose up -d db
POSTGRES_HOST=localhost npm run ci
POSTGRES_HOST=localhost npm run test:e2e -w @crm/server -- --runTestsByPath test/migration.e2e-spec.ts
POSTGRES_HOST=localhost POSTGRES_DB=crm_test npm run openapi
```

Для запуска на существующей рабочей базе отдельно применяются миграции:

```bash
POSTGRES_HOST=localhost npm run migration:run -w @crm/server
```

## Материал для анализа результатов НИР

Эксперимент подтверждает корректность проверенных сценариев единой модели
каталога и предложения, разграничения доступа, расчёта денежных значений
и контроля конкурирующих изменений. Снимки отделяют редактируемый каталог
от оформленного документа; транзакция связывает замену позиций и итоговой
суммы в одну операцию.

Проверки не измеряют экономический эффект внедрения, удобство работы
реальных менеджеров или производительность на большом объёме данных.
Позиции самой сделки пока отсутствуют: её сумма остаётся ручной и
не меняется при редактировании коммерческого предложения.
