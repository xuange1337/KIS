# Чек-лист выпуска

Проходится целиком перед каждым обновлением production. Пункт, который
нельзя подтвердить, — причина отложить выпуск, а не примечание к нему.

## До выпуска

- [ ] `npm run ci` проходит полностью (форматирование, линтер, сборки,
      тесты web и API, лицензии, секреты, конфигурация compose).
- [ ] `npm run audit:production` — нет critical и high.
- [ ] `docs/openapi.json` пересобран (`npm run openapi`), изменения
      контракта просмотрены в ревью.
- [ ] `CHANGELOG.md` дополнен, версия проставлена.
- [ ] Миграции проверены на копии production-базы: применение и откат.
- [ ] Новые переменные окружения добавлены в `.env.example` и
      `docker-compose.yml`, значения на стенде заданы.
- [ ] Снята резервная копия непосредственно перед обновлением:
      `scripts/backup.sh`, и она проверена `scripts/restore.sh --verify`.
- [ ] Известен способ отката: предыдущий образ и копия базы до обновления.

## Выпуск

- [ ] `docker compose up --build -d`.
- [ ] `api` и `web` перешли в состояние healthy.
- [ ] `curl -s <хост>/api/health/ready` отдаёт
      `{"status":"ok","database":"up","schema":"current"}`.
- [ ] В логе `api` есть имя применённой миграции.

## После выпуска

- [ ] Вход в интерфейс, открытие клиента, сделки и отчёта.
- [ ] Ошибка запроса возвращается в едином формате с `requestId`.
- [ ] Записи журнала действий появляются и не содержат персональных данных.
- [ ] В логах нет ошибок уровня error за первые 15 минут.
- [ ] Первая ночная резервная копия снята и прошла проверку.

## Откат

1. `docker compose down` и запуск предыдущего образа.
2. При несовместимой миграции — восстановление базы из копии,
   снятой до обновления: `scripts/restore.sh <копия> --production`.
3. Запись в журнал инцидента: причина, время простоя, потерянные данные.
