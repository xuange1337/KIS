- Refresh-токены больше не являются неотзываемыми: добавлены серверные сессии, SHA-256-хеш токена, ротация, обнаружение повторного использования и отзыв при logout.
- Refresh и logout защищены double-submit CSRF-токеном.
- Блокировка пользователя и смена пароля отзывают refresh-сессии.
- Добавлены liveness и readiness endpoints с проверкой PostgreSQL.
- Контейнер API запускается не от root.
- Docker Compose ожидает readiness API и проверяет web.
- Страницы загружаются отдельными чанками; стартовый JS сокращён примерно на две трети.
- React Router обновлён до версии без найденных audit-уязвимостей.
- Уязвимый Multer заменён безопасной версией через корневой override до перехода на следующий major NestJS.

## Зависимости и лицензии

Production audit не обнаруживает critical/high проблем. Остаётся moderate advisory `uuid`, транзитивно используемый `exceljs`. Уязвимый API генерации UUID не вызывается кодом CRM, но зависимость должна быть заменена или обновлена после появления совместимой версии. Принудительная несовместимая подмена не используется.

До коммерческого релиза требуется автоматическая генерация перечня лицензий и ручная проверка всех файлов, шрифтов и изображений. Нельзя заявлять юридическое соответствие продукта без оценки конкретного развёртывания.

## Архитектурные риски

- Все бизнес-таблицы относятся к одной организации; добавление tenant scope потребует миграции каждой сущности, индексов и полного набора negative e2e.
- Роль хранится непосредственно в пользователе; для нескольких организаций нужна membership-модель.
- Экспорты формируются синхронно и могут занимать HTTP worker.
- Файлы пока представлены ссылкой и не имеют безопасного upload pipeline.
- Аудит пишет payload запросов; перед расширением форм требуется централизованное маскирование чувствительных полей.

## Первый вертикальный срез

Первый срез включает серверные refresh-сессии, их ротацию и отзыв, health/readiness, безопасную версию Multer и Docker healthchecks. Срез подтверждается production build, 30 frontend-тестами, 84 API e2e и `docker compose config`.

Следующий P0-срез: организация, membership, tenant context, миграция существующих данных и межтенантные e2e для всех сущностей.
