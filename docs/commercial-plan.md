# Подробный план доработки до коммерческого использования

Редакция от 2026-10-22. Развивает `docs/roadmap.md` с учётом того, что уже
сделано после версии 1.1.0, и разбивает каждый этап на задачи с критериями
приёмки, зависимостями и рисками. Оценки — в рабочих днях одного
разработчика, включая тесты и документацию (так принято в репозитории).

## 0. Точка отсчёта

**Готово:** изоляция организаций, роли внутри организации, переключение
организации, приглашения по одноразовой ссылке, управление своей
организацией, серверные сессии, CSRF, журнал действий, идемпотентность,
optimistic locking, OpenAPI, бэкапы с проверкой восстановления, CI,
браузерные тесты, каталог товаров, состав коммерческого предложения.

**Не закоммичено:** каталог и состав КП, миграции `AddProducts` и
`AddOfferItems`, материалы НИР. Первое действие плана — довести это до
коммита с зелёным `npm run ci`.

**Нет вообще:** почты, самостоятельной регистрации, тарифов и оплаты,
вложений-файлов, позиций сделки, тегов, полей, воронок, дедупликации,
уведомлений, 2FA, юридических документов, внешних копий и мониторинга.

## 1. Принципы

1. **Сначала то, что блокирует продажу**, потом то, что её облегчает.
2. **Каждая задача закрывается тестом** (e2e API, компонентный или
   браузерный) и записью в `CHANGELOG.md`, `docs/openapi.json`,
   руководствах.
3. **Миграции только вперёд и обратимые**, проверяются миграционным тестом
   на базе с данными.
4. **Деньги и персональные данные — только с юридической оценкой.** Код делает
   соответствие возможным, но не заявляет его.
5. **Платящий заказчик важнее полноты.** После первых двух клиентов
   приоритеты берутся из их запросов, а не из этого списка.

## 2. Решения, которые нужны до старта (1–2 дня)

| Вопрос | Варианты | Рекомендация |
|---|---|---|
| Рынок | РФ / международный | от него зависят платёжный провайдер, 152-ФЗ, хостинг |
| Модель | облако (SaaS) / установка у заказчика | SaaS: проще обновлять и поддерживать |
| Хостинг | VPS в РФ (Selectel, Timeweb, Yandex Cloud) / Render, Fly | для РФ — российская площадка (персональные данные); Render годится только для демо |
| Платёжный провайдер | ЮKassa, CloudPayments, Т-Банк | ЮKassa: чеки 54-ФЗ из коробки |
| Почта | SMTP своего домена, Unisender, Mailganer, Postmark | внешний сервис плюс SPF/DKIM/DMARC |
| Юрлицо | ИП / ООО / самозанятый | влияет на НДС, договоры, чеки |
| Название и домен | | нужны для почты, сертификата, юридических текстов |

## Этап B. Самостоятельное подключение — 12–15 дней (блокирует продажу)

### B1. Транзакционная почта — 3 дня
- Модуль `mail`: интерфейс отправки, реализация SMTP, заглушка для тестов.
- Очередь отправки поверх существующих фоновых заданий: повтор с
  нарастающей паузой, итоговый статус, журнал без тела письма.
- Шаблоны (HTML и текст, русский): приглашение, сброс пароля, подтверждение
  адреса, смена пароля, истечение пробного периода, неоплата.
- Настройки в `.env`, проверка в `/health/ready` (без блокировки старта).
- Приёмка: приглашение и сброс пароля доходят письмом; без SMTP система
  работает и показывает ссылку администратору, как сейчас; ссылка в письме
  одноразовая, срок жизни проверен тестом.
- Риски: попадание в спам — настроить SPF, DKIM, DMARC до первой рассылки.

### B2. Подтверждение адреса — 1 день
- Поле `email_verified_at`, письмо со ссылкой, повторная отправка с лимитом.
- До подтверждения: вход разрешён, приглашать и подключать оплату нельзя.

### B3. Самостоятельная регистрация организации — 4 дня
- `POST /auth/register`: организация, администратор, пробный период, всё в
  одной транзакции с идемпотентностью.
- Защита: лимит по IP и адресу, проверка одноразовых почтовых доменов,
  CAPTCHA (hCaptcha/Turnstile), задержка одинакового ответа для
  существующих адресов.
- Экран регистрации, мастер первого запуска (название, часовой пояс, валюта,
  стадии воронки, пример данных или импорт).
- Приёмка: новый человек за 3 минуты оказывается в пустой организации с
  подсказками; повторная регистрация того же адреса не раскрывает его
  существование.

### B4. Пробный период и состояние организации — 2 дня
- Поля `plan`, `trial_ends_at`, `status` (`trial`, `active`, `past_due`,
  `suspended`, `closed`).
- Единая проверка состояния в guard: в `suspended` — только чтение и выгрузка.
- Баннер «осталось N дней», письма за 7, 3, 1 день и в день окончания.

### B5. Управление участниками — 2 дня
- Список, смена роли, исключение, передача владения, выход из организации.
- Инвариант: у организации всегда есть владелец; последнего не удалить.
- Отзыв сессий исключённого немедленно (механизм сессий уже есть).

### B6. Закрытие и удаление организации — 2 дня
- Закрытие с выгрузкой всех данных (JSON и CSV), отсрочка удаления 30 дней,
  окончательное удаление заданием с подтверждением по почте.

## Этап D. Деньги — 15–20 дней

Выполнять после первых 2–3 клиентов, оплаченных счётом вручную.

### D1. Тарифы и лимиты — 4 дня
- Таблица `plans` (код, цена, период, лимиты: пользователи, клиенты, сделки,
  хранилище, функции).
- `LimitsService`: проверка на сервере при создании пользователя, клиента,
  вложения; понятный код ошибки `PLAN_LIMIT_EXCEEDED` и экран «повысить тариф».
- Переход на тариф ниже — только если текущее использование укладывается.

### D2. Подписки — 4 дня
- Состояния: пробный, активна, просрочена (льготные 7 дней), приостановлена,
  отменена. Продление, смена тарифа с пересчётом остатка, отмена в конце периода.
- Ежедневное задание: переводит состояния, шлёт письма.

### D3. Приём платежей — 5 дней
- Интеграция ЮKassa: создание платежа, страница оплаты, вебхук.
- Вебхук: проверка подписи/запроса статуса у провайдера, идемпотентность по
  идентификатору платежа, повторная доставка безопасна.
- Сохранение способа оплаты для автопродления, возврат, чек 54-ФЗ через
  провайдера.
- Приёмка: тест на тестовом контуре провайдера; повторный вебхук не
  удваивает оплату; сбой сети не теряет платёж (сверка по расписанию).

### D4. Счета и документы — 3 дня
- Счёт на оплату PDF для юрлиц, акт, УПД; нумерация без разрывов в рамках года.
- Раздел «Биллинг»: история платежей, скачивание документов, реквизиты.

### D5. Панель оператора — 3 дня
- Отдельный контур доступа (не роль организации): список организаций,
  тариф, оплата, ручная корректировка, вход «от имени» с записью в журнал и
  уведомлением, блокировка.

## Этап F. Интеграции — по запросу заказчика

Не делать впрок. Каждая — отдельное направление с поддержкой.

- **Публичный API и ключи**: токены доступа организации с областями и
  лимитами, документация, вебхуки исходящие с подписью и повторами (6–8 дней).
- **Календарь** (iCal-подписка, затем Google/Яндекс) (3–5).
- **Почта** (IMAP/SMTP привязка, письма в карточке клиента) (10+).
- **Телефония** (Mango, Zadarma, Telphin) (5–8 на провайдера).
- **Формы на сайте и Telegram-бот** — приём лидов (3–4).
- **1С / бухгалтерия** (CommerceML, REST) (10+).

## 3. Календарь

Ориентир для одного разработчика, 5 рабочих дней в неделю.

| Недели | Этапы | Результат |
|---|---|---|
| 1 | A, решения из §2 | чистая база, выбранный стек и провайдеры |
| 2–4 | B | заказчик подключается сам |
| 3–5 | C (параллельно, юрист) | тексты и согласия |
| 5–8 | H1–H6 | продуктовая среда, копии, мониторинг |
| 8–11 | E1–E3 | вложения, позиции сделки, PDF |
| 11 | J1–J4 | закрытая бета, первые счета вручную |
| 12–16 | D | автоматическая оплата |
| 16–22 | E4–E13 | воронки, поля, теги, дедупликация, уведомления |
| 22–25 | G, I | 2FA, SSO, пентест, полировка |
| 25–28 | J, выход из беты | публичный запуск |

Итого **около 6–7 месяцев** одного разработчика; с двумя — 4–5 месяцев.

## 4. Минимальный путь до первого платящего клиента (≈ 10–11 недель)

A → B1–B5 → C1–C3 → H1, H3, H5 → E1, E2, E3 → J2, J4 → счёт вручную.

## 5. Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| Нет спроса на рынке | высокая | продавать раньше полноты, закрытая бета на неделе 11 |
| Юридические требования шире ожидаемых | средняя | юрист на этапе C, не после |

## 6. Определение «готово к коммерческому использованию»

- [ ] Новый заказчик регистрируется и работает без участия разработчика.
- [ ] Оплата проходит, чек выдан, документы скачиваются.
- [ ] Данные изолированы, это подтверждено тестами и внешним пентестом.
- [ ] Копии вынесены за пределы хоста, восстановление проверено на этой неделе.
- [ ] Есть алерты, дежурный знает, что делать, runbook'и проверены.
- [ ] Подписаны ToS, политика конфиденциальности, согласие, DPA; площадка
      соответствует требованиям рынка.
- [ ] Заказчик может выгрузить все свои данные и удалить организацию.
- [ ] Есть поддержка с регламентом, база знаний, страница состояния.
- [ ] Нагрузочные испытания подтверждают целевые показатели.
- [ ] Закрытая бета завершена, критичные замечания устранены.

## 7. Чего в плане нет намеренно

Мобильное приложение, встроенная телефония, ИИ-функции, маркетплейс
расширений, белая этикетка. Возвращаться к ним после 50 платящих
организаций, а не раньше.
