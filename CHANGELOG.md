# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация версий — [семантическая](https://semver.org/lang/ru/).

## [Не выпущено]

### Добавлено

- Повторяющиеся активности: правило «каждый день / неделю / месяц» и
  необязательный предел серии. Следующая активность создаётся при отметке
  текущей выполненной (одной транзакцией, при двойной отметке — один раз);
  дата считается от запланированной, месяц с 31 числа не «уплывает».
  Отмена серию заканчивает. Миграция `AddActivityRecurrence`.
- Управление составом организации: список участников, смена роли,
  исключение с немедленным закрытием сеансов, выход из организации.
  Экран «Организация» для администратора.
- Владелец организации: единственный закрывает организацию и передаёт
  владение (по паролю). Владелец всегда администратор и не может быть
  исключён, понижен или выйти. Для существующих организаций владельцем
  стал самый ранний администратор.
- Выгрузка всех данных организации одним JSON-файлом
  (`GET /organizations/current/export`, пишется в журнал).
- Закрытие организации по паролю и вводу названия: запись закрыта,
  чтение и выгрузка остаются 30 дней, владелец может вернуть организацию.
  По истечении срока данные удаляются заданием вместе с учётными
  записями, которым больше некуда входить.
- Почта в учётных записях и подтверждение адреса: письмо со ссылкой,
  повторная отправка, смена адреса (старая ссылка не подтверждает новый).
  Уникальны только подтверждённые адреса. Вход остаётся по логину.
- Самостоятельная регистрация организации (`POST /auth/register`):
  организация, администратор и пробный период 14 дней одной транзакцией,
  сеанс открывается сразу. Требуется принять условия использования.
- Восстановление пароля по почте (`POST /auth/password/forgot`): ответ
  одинаков для любого адреса, письмо уходит только на подтверждённый.
- Состояние организации (`trial`, `active`, `past_due`, `suspended`,
  `closed`). Окончание пробного периода переводит организацию в режим
  чтения: запись закрыта ответом 402 `ORGANIZATION_SUSPENDED`, чтение и
  выгрузки отчётов остаются. Напоминания за 7, 3 и 1 день и в день
  окончания, повторный запуск ничего не дублирует.
- Баннеры в интерфейсе: остаток пробного периода, блокировка записи,
  неподтверждённый адрес. Страницы регистрации, подтверждения адреса и
  «Забыли пароль?».
- Приглашать сотрудников может только тот, чей указанный адрес
  подтверждён.

### Изменено

- Название организации больше не уникально.
- Исходящая почта (SMTP, `MAIL_*` в `.env`): приглашение в организацию
  уходит письмом, если указан адрес и почта настроена. Ссылка по-прежнему
  возвращается администратору, сбой почты не ломает выдачу приглашения.
  Без `MAIL_HOST` почта выключена, поведение прежнее.
- Каталог товаров и услуг организации: артикул, описание, единица,
  цена и валюта; поиск, сортировка, архивирование и восстановление.
  Менеджер читает каталог, руководитель и администратор редактируют.
  Параллельные правки защищены проверкой версии.
- Состав коммерческого предложения из каталога, дробное количество
  до тысячных, снимок цены и названия. Сервер рассчитывает итог в копейках,
  округляя каждую строку; запрещает смешивать валюты и превышать предел суммы.
  Замена состава транзакционна и требует актуальную версию КП.
  Валюта предложения сохраняется независимо от последующих правок сделки.
- Участие в организациях: роль действует в пределах организации, один
  человек может работать в нескольких, переключение в меню.
- Приглашение сотрудника по одноразовой ссылке; присоединение к ещё
  одной организации текущей учётной записью.
- Просмотр и переименование своей организации.

## [1.1.0] — 2026-09-28

### Добавлено

- Мультитенантность: организации как граница изоляции данных,
  `organization_id` во всех бизнес-таблицах, централизованный tenant scope,
  20 межтенантных проверок.
- Контракт API: OpenAPI на `/api/docs`, файл `docs/openapi.json`,
  единый формат ответа об ошибке с `code`, `path`, `requestId`, `timestamp`.
- Наблюдаемость: сквозной `X-Request-Id` и структурированные JSON-логи
  в production.
- Проверка версии схемы: экземпляр с непримененными миграциями не стартует
  и не отвечает готовностью.
- Резервное копирование: `scripts/backup.sh` (дамп, вложения, версия схемы,
  контрольные суммы, ротация, опциональное шифрование),
  `scripts/restore.sh` (проверка целостности и восстановление),
  `docs/runbook-disaster-recovery.md`.
- Релизный контур: `npm run ci`, ESLint и Prettier, проверка секретов,
  проверка лицензий, `docs/release-checklist.md`.
- Предел размера тела запроса (`BODY_LIMIT`, по умолчанию 256 КБ).
- Optimistic locking карточек клиента и сделки: одновременная правка
  отклоняется с 409 вместо молчаливой потери изменений.
- Миграционный тест обновления с предыдущей схемы и нагрузочный smoke.
- CI на сервере: `.github/workflows/ci.yml`.
- Идемпотентность операций создания по заголовку `Idempotency-Key`.
- Версия в пути API (`/api/v1/...`) при сохранении прежних путей.
- Диагностика администратора `GET /api/diagnostics`.
- Защита несохранённых изменений в формах клиента и сделки.
- Смена собственного пароля и восстановление доступа по одноразовой
  ссылке, которую выдаёт администратор.
- Загрузка клиентов из CSV и XLSX с предпросмотром и отчётом об ошибках.
- Массовая смена ответственного и статуса у выбранных клиентов.
- Причина проигрыша сделки, отчёт по причинам и его выгрузка.
- Поиск по всем разделам сразу с вызовом по Ctrl+K.
- Браузерные сценарии критических потоков (Playwright) и запуск их в CI.
- Настраиваемый предел попыток входа (`LOGIN_RATE_LIMIT`).
- Фоновые выгрузки отчётов: очередь заданий, опрос состояния,
  скачивание готового файла, хранение суток.
- Светлая и тёмная схемы оформления с выбором «как в системе».
- Адаптивность от 360 точек: меню на телефоне в выдвижной панели.
- Автоматическая проверка доступности разметки (`axe-core`).
- Ссылка «Перейти к содержимому» для навигации с клавиатуры.

### Исправлено

- Администратор мог заблокировать себя или снять с себя роль и оставить
  систему без управления.
- Выход и «завершить все сессии» не отзывали уже выданный access-токен:
  доступ сохранялся до конца его срока.
- Повторное использование refresh-токена отзывало только одну сессию.
- CSRF-cookie не продлевалась и через 7 дней ломала обновление токена.
- Сортировка списков по неуникальному полю давала неустойчивый порядок:
  запись попадала на две страницы подряд или не попадала никуда.
- Ошибка разбора тела запроса отдавалась как внутренняя ошибка сервера.
- Список стадий в карточке сделки не имел доступного имени: программе
  чтения с экрана он объявлялся просто «список».
- Фоновая обработка выгрузок продолжалась после остановки приложения и
  обращалась к уже закрытому соединению.
- Тип активности обозначался только значком: подпись висела на `div`
  атрибутом `aria-label`, который экранный диктор игнорирует.
- Тест ленты активностей зависел от времени суток: после девяти вечера
  проверка «через три часа — сегодня» падала не из-за кода.

### Изменено

- Семантические токены оформления переведены на CSS-переменные:
  компоненты не знают о схеме, переключение не перерисовывает дерево.

- Журнал действий не хранит свободный текст и строку запроса: секреты
  отсеиваются, персональные поля заменяются пометкой, длина ограничена.
- Пароль базы данных обязателен: значения по умолчанию в исходниках больше нет.
- Форма входа тратит одинаковое время на существующий и несуществующий
  логин.

## [1.0.0] — 2026-09-16

Первая версия: пять модулей ТЗ, пять отчётов, экранные формы, ролевая
модель, серверные refresh-сессии, журнал действий, выгрузки CSV/XLSX/PDF,
развёртывание через Docker Compose.
