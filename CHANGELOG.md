# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация версий — [семантическая](https://semver.org/lang/ru/).

## [Не выпущено]

### Добавлено

- Мультитенантность: организации как граница изоляции данных,
  `organization_id` во всех бизнес-таблицах, централизованный tenant scope,
  20 межтенантных проверок.
- Контракт API: OpenAPI на `/api/docs`, файл `docs/openapi.json`,
  единый формат ответа об ошибке с `code`, `path`, `requestId`, `timestamp`.
- Наблюдаемость: сквозной `X-Request-Id` и структурированные JSON-логи
  в production.
- Проверка версии схемы: экземпляр с непримененными миграциями не стартует
  и не отвечает готовностью.
- Резервное копирование: `scripts/backup.sh` (дамп, вложения, версия схемы,
  контрольные суммы, ротация, опциональное шифрование),
  `scripts/restore.sh` (проверка целостности и восстановление),
  `docs/runbook-disaster-recovery.md`.
- Релизный контур: `npm run ci`, ESLint и Prettier, проверка секретов,
  проверка лицензий, `docs/release-checklist.md`.
- Предел размера тела запроса (`BODY_LIMIT`, по умолчанию 256 КБ).

### Исправлено

- Администратор мог заблокировать себя или снять с себя роль и оставить
  систему без управления.
- Выход и «завершить все сессии» не отзывали уже выданный access-токен:
  доступ сохранялся до конца его срока.
- Повторное использование refresh-токена отзывало только одну сессию.
- CSRF-cookie не продлевалась и через 7 дней ломала обновление токена.
- Сортировка списков по неуникальному полю давала неустойчивый порядок:
  запись попадала на две страницы подряд или не попадала никуда.
- Ошибка разбора тела запроса отдавалась как внутренняя ошибка сервера.

### Изменено

- Журнал действий не хранит свободный текст и строку запроса: секреты
  отсеиваются, персональные поля заменяются пометкой, длина ограничена.
- Пароль базы данных обязателен: значения по умолчанию в исходниках больше нет.
- Форма входа тратит одинаковое время на существующий и несуществующий
  логин.

## [1.0.0] — 2026-09-16

Первая версия: пять модулей ТЗ, пять отчётов, экранные формы, ролевая
модель, серверные refresh-сессии, журнал действий, выгрузки CSV/XLSX/PDF,
развёртывание через Docker Compose.
